# Continuous integration scope

The workflow runs on GitHub-hosted `windows-2022` and `ubuntu-24.04`, using Python 3.13.0. It installs the reviewed build/dependency artifacts, installs DeskTrace without dependency resolution, and executes `tools/verify.py`. That tool runs the complete existing 41-test unittest suite, `pip check`, CLI help, Unicode mock replay, good/bad/invalid exit contracts, manifest verification, outcome comparison and repeated-run summary. The workflow explicitly checks the test count. It needs no repository secrets or desktop authorization.

Tests of the Windows boundary use controlled mocks. Neither job launches UIA, a real app, Tk windows, a native dialog or a screenshot capture. A green CI run is **not real GUI acceptance** and does not extend the support matrix. Linux is not a native desktop backend. The independent Server 2022 GUI results are historical, separately retained evidence in [VM_ACCEPTANCE.md](VM_ACCEPTANCE.md), not generated by CI.

The workflow has contents-read permission, no persisted checkout credentials, no `pull_request_target`, no self-hosted runner, no publishing step, no cache and no artifact upload. Its test data is project-owned and non-sensitive. Full command output is available in job logs; `tools/verify.py` also writes numbered stdout/stderr and a summary under the temporary runner's `runs/`. Runner files are not permanent downloadable evidence. Review job output on failure; do not assume a skipped/missing job passed.
