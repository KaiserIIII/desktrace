# Continuous integration scope

The workflow runs on GitHub-hosted `windows-2022` and `ubuntu-24.04`, using Python 3.13.0. It installs the reviewed build/dependency artifacts, installs DeskTrace without dependency resolution, and executes `tools/verify.py`. That tool runs the complete existing 41-test unittest suite, `pip check`, CLI help, Unicode mock replay, good/bad/invalid exit contracts, manifest verification, outcome comparison and repeated-run summary. The workflow explicitly checks the test count. It needs no repository secrets or desktop authorization.

Tests of the Windows boundary use controlled mocks, including an explicit Windows platform for simulated worker responses. Neither job launches UIA, a real app, Tk windows, a native dialog or a screenshot capture. A green CI run is **not real GUI acceptance** and does not extend the support matrix. Linux is not a native desktop backend. The independent Server 2022 GUI results are historical, separately retained evidence in [VM_ACCEPTANCE.md](VM_ACCEPTANCE.md), not generated by CI.

The workflow has contents-read permission, no persisted checkout credentials, no `pull_request_target`, no self-hosted runner, no publishing step, no cache and no artifact upload. Its test data is project-owned and non-sensitive. `tools/verify.py` writes numbered stdout/stderr and a summary under the temporary runner's `runs/`; if verification fails, the workflow prints these logs while preserving the failure exit code. Runner files are not permanent downloadable evidence. Review job output on failure; do not assume a skipped/missing job passed.

These actions run on the hosted runner, not as installed product dependencies. Python/runner images are platform prerequisites, and their resolved versions are retained in job output. The initial Linux run failed two unit tests because the worker subprocess was mocked but the platform guard was not; the tests now explicitly enter their simulated Windows boundary, and the malformed-response check also asserts the specific error code. No test is skipped, no runtime behavior is changed, and the count remains 41. Actual outcomes belong to each workflow run. Locally executing equivalent commands or validating YAML cannot prove hosted success. Context7 documentation lookup was quota-limited; configuration was checked against the official action definitions and [GitHub security guidance](https://docs.github.com/en/actions/reference/security/secure-use).
